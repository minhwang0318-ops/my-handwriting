# 내 손글씨

내 손글씨를 한 번 등록하면, 타이핑한 글을 내가 손으로 쓴 것처럼 보이는 페이지(PDF/PNG)로 만들어 주는 앱입니다.
서버 없이 브라우저 안에서만 동작하고, 아이폰·아이패드에서는 사파리의 "홈 화면에 추가"로 설치해서 씁니다(PWA).

## 진행 상황

| 단계 | 내용 | 상태 |
|---|---|---|
| 1 | 한글 유틸(분해/합성/배치 분류)과 테스트, 기준 글자 자모 영역 JSON 생성 | 완료 |
| 2 | 따라 쓰기 화면: 칸, 획 기록, 자모 배정, 검증, 다시 쓰기, 저장 | 완료 |
| 3 | 변환 화면: 직접 쓴 글자 + 스타일 프로필, PDF/PNG | 완료 |
| 4 | 자모 조합과 비교 화면 | 완료 |
| 5 | 프로필 슬라이더, 데이터 내보내기/가져오기, 없는 글자 추가 쓰기, 오프라인(서비스 워커) | 완료, 확인 대기 |
| 6 | 예전에 쓴 편지·레포트 사진 올리기(반자동) | 완료, 확인 대기 |

## 실행

Node 22 이상이 필요합니다.

```bash
npm install
npm run dev          # http://localhost:3000
npm test             # 단위 테스트 (Vitest)
npm run regions      # 자모 영역 JSON 다시 만들기 (public/data, 약 20초)
npm run icons        # PWA 아이콘 다시 만들기
```

- 따라 쓰기: `http://localhost:3000/write`
- 변환: `http://localhost:3000/convert`
- 조합 품질 비교: `http://localhost:3000/compare`
- 설정: `http://localhost:3000/settings`
- 사진에서 가져오기: `http://localhost:3000/upload`
- 개발 모드(`npm run dev`)에서는 처음 화면 아래에 "시험 데이터 넣기/지우기" 버튼이 있습니다.
  - 시험 데이터 1: 가·나·다·라·마·아·이·고·. 9자 × 2벌. 좌표로 만든 단순한 획입니다.
  - 시험 데이터 2: 등록 글자 473자. 기준 글꼴의 자모 영역을 가늘게 깎은 뼈대를 자모마다 조금씩 비튼 획입니다. 먼저 `npx tsx scripts/dev/build-skeleton-samples.ts`로 `public/dev/skeleton-samples.json`(약 7MB)을 만들어야 합니다.
  - 둘 다 진짜 손글씨가 아닙니다. 동작 확인용입니다. 글꼴 뼈대를 손글씨처럼 쓰는 방식은 제품 기능으로 쓰지 않습니다(요청서의 "안 된 방법" 2번).
- `npx tsx scripts/dev/render-test-pdf.ts out.pdf`: 시험 데이터로 PDF를 만듭니다.
- 1단계 확인 화면: `http://localhost:3000/check/regions`
- 특정 글자만 쓰기: `/write?chars=뷁쀍` (변환 화면의 "지금 쓰기"가 이 주소를 쓸 예정)

아이패드에서 같은 와이파이로 열어 보려면 `npm run dev -- -H 0.0.0.0`으로 띄우고 `http://<맥 IP>:3000`으로 접속하면 됩니다.

### 폰·아이패드에 설치 (PWA)

배포 주소: **https://minhwang0318-ops.github.io/my-handwriting/**

`main` 브랜치에 올리면 GitHub Actions(`.github/workflows/pages.yml`)가 순서대로 처리합니다.
1. 테스트를 돌립니다.
2. 정적 파일로 빌드합니다(`NEXT_EXPORT=1`, `NEXT_PUBLIC_BASE_PATH=/저장소이름`).
3. GitHub Pages에 배포합니다.

서버에 저장되는 데이터는 없습니다. 손글씨는 각 기기의 브라우저 저장소에만 있습니다.

아이패드·아이폰에 설치하는 방법:
1. 사파리에서 위 주소를 엽니다.
2. 공유 버튼 → "홈 화면에 추가"를 누릅니다.
3. 홈 화면의 "내 손글씨" 아이콘으로 엽니다. 처음 한 번 열 때 화면과 글꼴(약 6MB)을 받아 두므로, 그다음부터는 오프라인에서도 열립니다.
4. 사파리에서 쓴 글씨와 홈 화면 앱에서 쓴 글씨는 저장소가 따로일 수 있습니다. 한쪽에서만 쓰고, 옮길 때는 설정 → 내보내기/가져오기를 쓰세요.

로컬에서 정적 빌드를 확인하려면:

```bash
NEXT_EXPORT=1 NEXT_PUBLIC_BASE_PATH=/my-handwriting npm run build   # out/ 에 생김
```

- 개발 서버(`npm run dev`)가 도는 중에 빌드하면, 둘이 같은 `.next` 폴더를 써서 개발 서버가 500 오류를 냅니다. 개발 서버를 끄고 빌드하세요.
- 서비스 워커는 배포판에서만 등록됩니다. 개발 서버에서는 화면 갱신을 방해해서 쓰지 않습니다.
- iOS의 오프라인과 "홈 화면에 추가"는 HTTPS 주소에서만 제대로 됩니다.

## 등록 글자

- 조합용 202자 (필수): 초성 19 × ㅏ/ㅗ/ㅘ × 받침 없음/ㄴ, ㅇ + 모음 21 × 받침 없음/ㄴ, 아/오 + 받침 27. 중복은 뺍니다.
  초성 6벌 × 19, 중성 2벌 × 21, 종성 2벌 × 27이 모두 들어 있는지는 테스트로 확인합니다.
- 영문 대소문자·숫자·기호 86자.
- 자주 쓰는 한글 185자 (선택). 손으로 고른 목록이며, 빈도 통계에서 뽑은 것은 아닙니다.

## 자모 영역 계산 방법

글자마다 128×128로 렌더링한 뒤 다음 순서로 계산합니다.

1. **모음+받침**: 같은 모음·받침에 초성 19개를 바꿔 끼운 글자들의 공통 부분입니다. 4px 허용 폭으로 찾고, 100% 공통부터 시작해 안 되면 95%, 90%로 낮춥니다.
2. **초성**: 같은 초성·같은 배치·같은 받침 유무에서 모음을 바꾼 글자들의 공통 부분입니다. 여기서 "같은 배치 모음들이 공유하는 획"(가로형의 ㅡ, 세로형의 세로획)은 뺍니다.
3. **받침**: 기준 글꼴에서는 받침이 맨 아래에 따로 놓이므로, 다음 순서로 고릅니다.
   - 맨 아래 빈 줄 띠 아래쪽을 받침으로 합니다.
   - ㅜ·ㅠ·ㅝ·ㅞ·ㅟ는 다리가 받침 높이까지 내려오므로, 바닥에서 받침 높이만큼을 받침으로 합니다.
   - 빈 줄 띠가 없으면 바닥의 획 덩어리를 받침으로 합니다.
   - 이 방법은 획이 깔끔하게 떨어진 기준 글꼴에서만 씁니다. 손글씨에 쓰지 않습니다(손글씨에서는 실패했던 방법입니다).
4. 나머지 잉크 픽셀은 가장 가까운 씨앗(초성/모음)에 배정합니다.

## 따라 쓰기 (2단계)

- 칸 = 기준 글꼴의 em 상자. 좌표는 칸 기준 0..1로 저장합니다. 필압(펜만), 획 시작 시간, 점별 시간도 저장합니다.
- 입력: Pointer Events.
  - 펜, 마우스, 손가락 모두 받습니다.
  - 펜을 한 번이라도 쓰면 그 화면에서는 손가락(터치) 입력을 손바닥으로 보고 무시합니다.
  - `getCoalescedEvents`로 빠른 획도 촘촘하게 받습니다.
- 자모 배정:
  - 각 점을 가장 가까운 기준 자모에 붙이고, 획 길이 가중으로 비율을 셉니다.
  - 두 자모에 각각 25% 이상 걸치면 경계에서 나눕니다. 나눈 조각은 경계 점을 공유합니다.
  - 5%보다 짧은 조각은 옆 조각에 붙입니다.
- 검증 (`src/lib/strokes/validate.ts`의 `DEFAULT_VALIDATE`, settings의 `validateConfig`로 덮어쓸 수 있음):
  - 허용 띠 폭: 칸 너비의 10%.
  - 통과 조건 1: 자모 획 길이의 60% 이상이 자기 띠 안에 있어야 합니다.
  - 통과 조건 2: 기준 자모 픽셀의 50% 이상이 획에서 칸 너비 10% 이내에 있어야 합니다(덮임).
  - 탈락: 자모가 빠짐(배정된 획 길이가 칸 너비의 2% 미만), 또는 칸 밖으로 2% 넘게 나감.
  - 획 모양, 기울기, 굵기는 보지 않습니다.
- 탈락하면 이유를 보여주고, 탈락한 자모의 띠를 주황색으로 칠합니다. "다시 쓰기"를 하거나 "나중에"로 다시 쓰기 목록에 넣을 수 있습니다.
- 같은 글자를 다시 쓰면 한 벌씩 더 쌓입니다. 저장된 벌은 썸네일로 보이고 지울 수 있습니다.

### 맥북 트랙패드로 쓰기

브라우저는 트랙패드의 손가락 위치를 알 수 없고 커서 움직임만 받습니다. 그래서 "펜이 종이에 닿은 상태"를 따로 정합니다(`src/lib/strokes/trackpad.ts`).

- **스페이스 바를 누른 채** 트랙패드에서 손가락을 움직이면 써집니다. 떼면 획이 끝납니다. 커서가 칸 위에 있을 때만 동작하고, 그동안은 페이지가 스크롤되지 않습니다.
- **톡** 한 번 → 쓰기 시작, 다시 **톡** → 멈춤. 움직이지 않고 짧게(0.35초 안) 누른 것만 '톡'으로 봅니다.
- 누른 채 끌기도 됩니다. macOS 손쉬운 사용의 "세 손가락으로 드래그하기"도 여기에 들어갑니다.
- 펜이 내려간 동안 칸 테두리가 주황색이 되고 "● 펜 내림"이 보입니다. 칸 밖으로 나가거나 Esc를 누르면 펜이 올라갑니다.
- 따라 쓰기 화면의 "트랙패드로 쓰기 (맥북)"로 켜고 끕니다.
  - 처음에는 터치가 없고 마우스·트랙패드만 있는 기기에서 자동으로 켜집니다.
  - 아이패드·아이폰에서는 꺼져 있어서 펜·손가락 입력은 그대로입니다.
- 트랙패드 획은 필압이 없으므로, 변환할 때 굵기가 획을 따라 완만하게 바뀝니다.

## 변환 (3단계)

직접 쓴 글자만 씁니다. 같은 글자를 여러 벌 썼으면 번갈아 씁니다. 쓴 적 없는 글자는 그 자리를 비워 두고 "없는 글자" 목록에 넣습니다. "지금 쓰기"를 누르면 그 글자들로 따라 쓰기 화면이 열립니다.

미리 계산하지 않은 글자(등록 글자 473자 밖)의 자모 영역은 따라 쓰기 화면을 열 때 브라우저에서 같은 알고리즘으로 계산합니다.

### 스타일 프로필을 어떻게 해석했는지

요청서에 단위가 적혀 있지 않은 값은 아래처럼 해석했습니다.

| 값 | 해석 |
|---|---|
| `size_mm` | 칸(em 상자) 한 변의 길이. 글자 잉크는 그보다 작음 |
| `*_px` | em(칸)의 1/100 |
| `slant` | 기울기 tan 값. 잉크 아래쪽을 고정하고 위를 민다 |
| `keep_size_diff` | 한글만 적용. 글자 잉크 높이를 중앙값 쪽으로 (1-keep)만큼 당김 (0.75~1.3배로 제한). 영문·숫자는 따라 쓴 크기 그대로 |
| `elastic_px` | 부드러운 사인파 변위장의 대략적인 진폭 |
| `rot_deg`, `scale_sd` | 글자마다 뽑는 회전(표준편차, 도)과 크기(표준편차, 비율) |
| `baseline_*`, `size_*` | 줄마다 새로 시작하는 AR(1). sd는 정상 분포의 표준편차 |
| `line_slope_mm` | 줄마다 뽑는 값(표준편차). 한 줄 너비를 지나는 동안 오르내리는 양 |
| `char_gap`, `word_space` | em 대비 비율. `*_var`는 변동계수. 글자 간격은 잉크 끝에서 잉크 시작까지 |
| `left_margin_sd_mm` | 줄 첫머리 위치의 표준편차 |
| `pressure` | 0이면 굵기 일정, 1이면 필압 0~1에 따라 0~2배 |
| `pressure_scale_px` | 필압이 없는 입력에서 만들어 넣는 굵기 변화의 파장 |
| `smooth_sigma` | 1px 간격으로 다시 찍은 점에 적용하는 가우시안 σ(점 개수) |
| `pen_mm` | 요청서에 없어서 새로 추가함. 기본 굵기 0.42mm |

배치 규칙:
- 줄노트의 선에는 em 상자 높이 0.9 지점을 맞춥니다.
- 낱말이 오른쪽 여백을 넘으면 줄을 바꾸고, 한 줄보다 긴 낱말은 글자 단위로 넘깁니다.
- 같은 글과 같은 "다시 섞기" 횟수면 항상 같은 결과가 나옵니다(시드 고정).

### 내보내기

- PDF는 벡터입니다. 획을 굵기 단계(0.03mm)별 폴리라인으로 나눠 그립니다. 시험 데이터 기준 2쪽에 약 410KB였습니다.
- PNG는 쪽마다 한 장씩, 200dpi입니다. 미리보기와 같은 그리기 코드를 씁니다.

## 자모 조합 (4단계)

직접 쓴 글자가 없는 한글만 조합합니다. 변환 화면의 "자모 조합 사용"으로 끌 수 있습니다.

1. 직접 쓴 한글의 자모 획(따라 쓰기에서 자모별로 나눠 저장한 것)을 모읍니다. 자모와 벌별로 모읍니다.
   - 초성 6벌: 배치 3종 × 받침 유무.
   - 중성 2벌: 받침 유무.
   - 종성 2벌: 가로형 모음 아래 / 그 외.
2. 대상 글자의 자모마다 같은 자모·같은 벌의 조각을 고릅니다.
   - 여러 벌이 있으면 번갈아 씁니다.
   - 맞는 벌이 없으면 비슷한 벌로 대신합니다. 초성은 같은 배치, 그다음 같은 받침 유무 순입니다. 비교 화면에 "다른 벌로 대신"으로 표시됩니다.
3. 조각을 원래 글자의 기준 자모 상자에서 대상 글자의 기준 자모 상자로 옮깁니다.
   - 가운데를 맞추고, 가로세로 비율 변형은 ±35%까지만 합니다(넓이 배율은 유지).
   - 그래서 쓴 사람이 기준보다 조금 비켜 쓰거나 크게 쓴 버릇은 그대로 따라갑니다.
4. 필요한 자모가 하나라도 없으면 조합하지 않고 "없는 글자"로 남깁니다.

조합용 202자를 모두 쓰면 한글 11,172자를 모두 조합할 수 있습니다. 가짜 상자로 만든 단위 테스트로 확인했습니다.

비교 화면(`/compare`)은 직접 쓴 글자 옆에, 그 글자를 빼고 나머지 글자의 자모로 조합한 결과를 나란히 보여줍니다. 아래 "아무 글자나 조합해 보기"에서는 쓰지 않은 글자도 조합해 볼 수 있습니다.

### 4단계에서 바꾼 자모 영역 계산

비교 화면에서 조합 글자가 비뚤어진 원인을 따라가 보니, 대상 글자의 기준 자모 상자가 잘못 칠해진 픽셀 때문에 부풀어 있었습니다. 그래서 아래를 바꿨습니다.

- 상자는 양 끝 3% 픽셀을 빼고 잡습니다.
- 가장 가까운 씨앗 배정은 잉크를 따라 거리를 잽니다. 그래서 이어진 획은 같은 자모로 칠해집니다.
- 떠돌이 씨앗을 정리합니다. 어떤 자모의 씨앗이 30% 미만만 있는 덩어리에서는 그 씨앗을 지웁니다(예: 주·수의 가로획 끝, 위의 ㅇ 테두리).
- 섞임형은 따로 다룹니다.
  - 모음 공통 부분을 2px, 100%로 찾고, 초성 공통 부분은 4px 허용으로 찾습니다.
  - 칸 너비 52% 이상 이어지는 가로 줄은 모음 가로획(ㅗ·ㅜ·ㅡ)으로 봅니다.

## 설정과 데이터 (5단계)

### 설정 화면 (`/settings`)

- **스타일 프로필**: 5가지 기준의 21개 값을 슬라이더로 바꾸고, 잉크 색을 고를 수 있습니다.
  - 위쪽 미리보기에 내 글씨로 바로 그려집니다. 미리보기 문장은 바꿀 수 있습니다.
  - 바꾸면 바로 저장되고, 변환 화면에도 적용됩니다.
  - 예전에 저장한 프로필에 없는 항목은 기본값으로 채웁니다(`mergeProfile`).
- **따라 쓰기 검증 기준**: 띠 폭, 띠 안 비율, 덮임 비율, 덮임 거리, 칸 밖 여유를 슬라이더로 바꿉니다.
- **데이터**
  - 내보내기: 모든 벌, 다시 쓰기 목록, 설정을 JSON 파일 하나로 받습니다.
  - 가져오기는 두 가지입니다.
    - 합치기: 있는 벌은 두고 같은 id가 없는 벌만 더합니다. 설정은 바꾸지 않습니다.
    - 바꾸기: 확인을 받은 뒤 전부 파일 내용으로 바꿉니다.
  - 다른 앱의 파일, 깨진 파일, 더 새 버전의 파일은 거절합니다. 모양이 잘못된 벌은 빼고 몇 벌 뺐는지 알려줍니다.
  - 모두 지우기.

### 없는 글자 추가 쓰기

1. 변환 화면의 "지금 쓰기"를 누르면 그 글자들로 따라 쓰기 화면이 열립니다.
2. 저장하면 아직 안 쓴 다음 글자로 넘어가고, 몇 자 남았는지 보여줍니다.
3. 다 쓰면 "변환 화면으로 돌아가기" 안내가 나옵니다.
4. 변환 화면은 돌아올 때 새로 쓴 글자를 다시 불러옵니다.

### 오프라인

서비스 워커가 설치될 때 다섯 화면, 각 화면이 쓰는 JS·CSS, 기준 글꼴, 자모 데이터, 아이콘을 미리 받아 둡니다. PDF 만들기(jsPDF)는 변환 화면과 함께 불러와서, 처음부터 오프라인이어도 됩니다.

## 사진에서 내 글씨 가져오기 (6단계)

예전에 쓴 편지나 레포트 사진을 올리고, 그 내용을 줄별로 타이핑하면 반자동으로 글자를 가져옵니다. 사진은 기기 안에서만 처리하고 어디에도 올리지 않습니다.

1. **글씨만 흑백으로**
   - 회색 변환은 빨강·초록 채널 위주라서, 파란 괘선이 옅어집니다.
   - 주변 평균보다 어두운 곳을 잉크로 잡습니다(적응형 이진화, "잉크 감도"로 조절).
   - 얇은 가로 괘선은 지웁니다. 너비의 25% 이상 이어진 줄, 또는 행 전체의 35% 이상이 잉크인 행 중 두께 4px 이하인 부분이 대상입니다.
2. **줄 찾기**: 잉크 덩어리들의 세로 범위가 겹치는 높이를 한 줄로 묶습니다.
3. **글자 묶기**: 가로로 겹치거나 가까운 덩어리를 합치되, 합친 너비가 글자 하나 정도(높이의 1.15배)까지만 합칩니다. 자모 단위로는 자르지 않습니다(요청서의 "안 된 방법" 1번).
4. **짝 짓기**: 입력한 글자 수만큼 상자를 묶습니다(동적 계획법).
   - 각 묶음의 너비가 그 글자의 예상 너비(한글 0.85, 영문 0.55~0.7, 문장부호 0.3, 높이 대비)에 가깝고, 묶음 안의 빈틈이 작은 쪽을 고릅니다.
   - 상자가 모자라면 가장 넓은 상자를 잉크가 가장 적은 세로줄에서 나눕니다.
5. **획으로**
   - 상자 안 잉크를 세선화해 뼈대를 선으로 따라갑니다.
   - 크기는 줄 단위로 맞춥니다(줄 글자 높이 → 칸의 0.8). 그래서 같은 줄 안의 크기·높이 차이는 쓴 그대로 남습니다.
6. **확인**: 자모를 배정하고 느슨한 검증을 합니다(띠·덮임 거리 1.5배, 띠 안 비율 70% 이상). 통과한 칸만 처음부터 "저장"에 체크됩니다. 글자를 고치거나 체크를 빼고 저장합니다.
7. **간격 반영(선택)**: 띄어쓰기 위치를 이용해 글자 간격과 띄어쓰기 폭을 잰 중앙값을 스타일 프로필에 넣을 수 있습니다.

저장한 글자는 `source: "photo"`로 표시되고, 따라 쓴 글자와 똑같이 변환·조합에 쓰입니다.

## 알려진 한계

- 영역 결과는 일부 글자만 눈으로 확인했습니다. 202자, 자주 쓰는 185자, 그리고 디버그 이미지로 본 몇십 자입니다. 11,172자 전체는 확인하지 않았습니다.
- 눈에 띄는 오차:
  - ㅇ 초성의 오른쪽 테두리 일부가 모음 색으로 칠해지는 글자가 있습니다(예: 위, 웨).
  - ㅜ·ㅠ 다리 끝 몇 px가 받침 쪽으로 들어갑니다(예: 운, 국).
- 스크립트 출력 기준 수치:
  - 받침 경계 빈 줄을 못 찾아 덩어리 규칙을 쓴 글자가 884자입니다. 이 글자들은 따로 확인하지 않았습니다.
  - 씨앗을 못 찾은 글자가 7자 있습니다(어느 글자인지는 출력하지 않음).
- 브라우저가 그린 기준 글자와 스크립트가 그린 글자의 잉크 겹침은 평균 약 90%입니다(확인 화면 상단에 표시). 색은 "가장 가까운 자모" 지도로 칠하므로 어긋난 픽셀도 칠해집니다. 다만 검증(2단계)에서 이 차이가 문제가 되는지는 아직 모릅니다.
- 등록 글자 목록은 고정이고, 겹받침 등 일부 글자는 조합으로만 만들어집니다(4단계).
- 오프라인은 맥의 배포판 서버(`localhost`)를 끈 상태로만 확인했습니다. 아이패드 실기기와 HTTPS 배포, "홈 화면에 추가"는 확인하지 않았습니다.
- 데이터는 기기 브라우저 저장소에만 있습니다. `navigator.storage.persist()`를 요청하지만, iOS는 저장 공간이 부족하면 지울 수 있습니다. 내보내기로 백업하세요.
- **사진 가져오기는 진짜 손글씨 사진으로 확인하지 않았습니다.** 글꼴 뼈대 시험 데이터로 그린 줄노트 이미지(`scripts/dev/render-test-png.ts`)로만 해 봤습니다. 그 이미지 기준:
  - 4줄을 모두 찾았고, 33칸 중 20칸이 자동으로 저장 대상이 됐습니다.
  - 글자끼리 닿아 있으면(예: "하늘이"의 ㅏ와 ㄴ) 그 칸은 잘못 잘립니다. 검증에서 대부분 빠지지만, 모양이 우연히 맞는 칸(옆 글자 조각이 "이"로 통과)이 하나 있었습니다. 저장 전에 눈으로 확인해야 합니다.
  - 상자 경계를 손으로 옮기는 기능은 없습니다. 틀린 칸은 빼는 것만 됩니다.
  - 사진 글씨는 쓴 순서와 필압이 없고, 세선화 때문에 획 끝이 조금 짧아지거나 가지가 생길 수 있습니다.
- 내보내기 파일이 큽니다. 시험 데이터 473자 기준 약 7MB입니다(점 좌표를 그대로 저장).
- 따라 쓰기는 앱 안 브라우저에서 마우스 드래그와 가짜 펜·터치 이벤트로만 시험했습니다. 실제 아이패드 + Apple Pencil과 폰 손가락 입력은 확인하지 않았습니다.
- 검증 기준값(60%, 50%, 띠 10%)이 실제 손글씨에 너무 엄하거나 너그러운지는 아직 모릅니다. 실제로 써 보고 조정해야 합니다.
- 기준 글자 영역 오차(예: 가·개의 ㄱ 꼬리 끝이 모음 색)는 그 부근 획의 자모 배정에 영향을 줄 수 있습니다.
- 변환은 시험 데이터(좌표로 만든 획)로만 확인했습니다. 진짜 손글씨로 얼마나 자연스러운지는 확인하지 않았습니다.
- 기본값(크기 10.5mm, 줄 간격 9.2mm)으로 그리면 줄과 줄이 거의 닿습니다. 원래 프로토타입에서 `size_mm`가 무엇을 기준으로 한 값인지 알 수 없어서, 위 해석대로 두었습니다. 5단계 슬라이더에서 조정할 수 있게 합니다.
- PNG 저장은 브라우저 다운로드를 실제로 눌러 보지 않았습니다. PDF는 파일로 만들어 열어 확인했습니다.
- 따라 쓰기 검증에서, 마침표처럼 톡 찍는 글자가 늘 "빠졌어요"로 탈락하던 문제를 4단계에서 고쳤습니다. 이제 획이 하나도 배정되지 않았을 때만 "빠짐"입니다.
- **조합 품질은 진짜 손글씨로 확인하지 않았습니다.** 글꼴 뼈대 시험 데이터로만 봤습니다. 그 데이터에서도 보이는 문제:
  - 괜: 조합한 ㄱ이 ㅙ와 겹칩니다.
  - 법·변·서: 중성 비율 제한에 걸립니다.
  - 왜·웨: 가로획 일부가 아직 초성 색입니다.
- 자모 조각은 따라 쓰기의 자모 배정을 그대로 씁니다. 배정이 틀린 획 조각(예: 다른 자모 쪽으로 간 획 끝)은 조합 글자에서 엉뚱한 자리로 갑니다.
